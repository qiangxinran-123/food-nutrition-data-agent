# 数据质量判定口径说明

这份文档回答一个关键问题：**在这个项目里，什么情况算问题。**

它不是统计学上的绝对真理，而是当前工具采用的判定口径。规则分为两层：

- 通用规则：任何表格数据都可以使用，例如空值、重复行、数字无法解析。
- 当前数据集规则：只适用于 `off_52k_v1`，例如条码允许几位、营养值最大是多少、哪些标签算不可用。

当前数据集的具体数值都写在 `config/profiles/off_52k_v1.json` 中。换数据集时，应重写这份说明书，而不是把新数据硬套到旧阈值上。

## 一张表看懂

| 问题类型 | 当前判定方式 | 重要提醒 |
|---|---|---|
| 缺失值 | 空值、空字符串、按字段声明的特殊词 | `unknown` 只对某些字段算缺失，不能全局处理 |
| 重复数据 | 当前只检查 `code` 是否相同 | 条码相同即判为重复 |
| 异常值/噪声 | 业务硬范围 + 统计尾部 | 统计尾部不一定是错误 |
| 类型/格式 | 类型能否解析、是否为有限数字、是否匹配格式 | 格式不标准不等于数据一定错误 |
| 字段冲突 | 字段之间是否满足换算关系或大小关系 | 冲突表示“可疑”，不是自动判错 |
| 标签错误 | 标签是否在允许集合内，以及是否可用 | “不可用”与“非法”要分开 |
| 类别不平衡 | 有效类别中少数类的占比和最大/最小比例 | 不可用标签不参加类别比例计算 |

## 1. 什么算缺失值

判定一个单元格缺失，命中任意一种即可：

1. 真正的空值，例如表格里的空白单元格；
2. 空字符串或纯空格；
3. 当前字段明确声明为缺失的特殊词。

特殊词必须按字段声明，因为同一个词在不同字段里含义不同。例如：

- `nutriscore_grade = unknown`：表示没有可用评分，算标签不可用；
- `categories = unknown`：表示没有类别信息，算缺失；
- `categories_en = en:null`：表示英文类别为空，算缺失；
- `brands = NA`：没有贸然当缺失，因为 `NA` 也可能只是一个品牌名称。

这就是为什么缺失值需要单独讨论：它不是单纯判断“格子是不是空的”，还要判断某些文字是不是在这个字段里代表“没有”。

## 2. 什么算重复数据

当前数据集只检查一种重复：`code` 相同的多行。条码被当作商品主键，所以这是严重问题。

当前数据共有 52,000 行，其中 2,000 组、每组 2 行拥有相同条码，因此冗余行也是 2,000 行。这 2,000 行是从原来的 50,000 行中随机抽取并复制加入的测试数据，原条码保持不变。原 50,000 行数据库已被这份 52,000 行数据覆盖。

检测工具本身仍支持按多列、全部字段或排除某些字段来判重，但当前 `off_52k_v1` 配置只启用 `code` 这一条规则。

## 3. 什么算异常值或噪声

当前分成两种力度。

### 3.1 硬范围异常

如果数值超出了业务上不可能的范围，就判为硬异常。例如每 100 克食品中：

- 蛋白质、脂肪、碳水、糖、纤维、盐、钠应在 0 到 100 克之间；
- 能量千卡应在 0 到 900 千卡之间；
- 能量千焦应在 0 到 3766 千焦之间。

这类问题比较可信，例如盐含量 6850 克/100 克显然不合理。

### 3.2 统计尾部异常

用多数数据所在的范围做参照。具体做法是先找第 25% 和第 75% 的位置，计算中间范围，再把远离该范围 5 倍距离的数据列为候选。

它用来提示“这个值明显比大多数商品更极端”。但高糖、高盐或高纤维食品本身可能真的存在，所以这类只标为低严重度，建议复查，不建议直接删除。

当前硬范围违规 1,063 个单元格；统计尾部候选 2,934 个单元格。两者可能命中同一行。

## 4. 什么算类型或格式问题

判定包括：

- 本应是数字的字段，内容无法转成数字；
- 数值出现无穷大、负无穷大等非有限值；
- 本应是日期的字段无法解析成日期；
- 本应是布尔值的字段出现无法识别的值；
- 字段内容不匹配为该字段配置的格式。

当前最明确的格式规则是商品条码：只接受 8、12、13、14 位纯数字。发现 207 个条码长度不符合该规则。

这 207 个条码不一定是假货或错误数据，也可能是内部编码。所以它被标为中等严重度，需要结合来源确认。

## 5. 什么算字段冲突

字段冲突指两个或多个字段单独看都正常，但放在一起互相矛盾。

当前配置了四条规则：

| 规则 | 允许误差 |
|---|---|
| 千焦 ≈ 千卡 × 4.184 | 允许相对误差 15% |
| 盐 ≈ 钠 × 2.5 | 允许相对误差 20%，另加 0.01 的绝对误差 |
| 糖不应明显超过总碳水 | 允许总碳水的 5% 再加 0.5 克 |
| 饱和脂肪不应明显超过总脂肪 | 允许总脂肪的 5% 再加 0.5 克 |

当前四条规则分别命中 3,064、203、28、20 行。

如果参与比较的任一字段为空，这一行跳过，不会因为缺数据被误判为冲突。

“冲突”表示两个字段至少有一个值得怀疑，并不自动说明哪一个是错的。清洗时可以选择重算派生字段、保留可信来源，或者先标记待人工确认。

## 6. 什么算标签错误

以 `nutriscore_grade` 为例，标签分成三类：

- 有效标签：`a`、`b`、`c`、`d`、`e`；
- 不可用标签：`unknown`、`not-applicable`、空值；
- 非法标签：不在有效集合、也不在不可用集合里的值。

当前数据没有非法标签，但有 29,201 条不可用标签：

- `unknown`：27,610 条；
- `not-applicable`：1,590 条；
- 空值：1 条。

“不可用”不等于“拼写错误”。这些标签不能直接用于有监督训练，但也不应被强行猜成 A 到 E 中的某一类。

## 7. 什么算类别不平衡

只统计有效标签，不把 `unknown`、`not-applicable` 和空值算成类别。

当前判定条件为任意一条：

- 最小类别占总有效标签的比例低于 15%；
- 最大类别数量与最小类别数量的比值超过 5。

当前 A 到 E 的有效分布中，最小类别 B 占 10.95%，最大/最小比例为 2.57，因此被判定为轻度不平衡。

这表示训练时需要采用分层抽样、类别权重或补充少数类样本，不代表原始数据必须被复制或删除。

## 8. 为什么缺失值讨论得最细

因为缺失值经常藏在普通文字里，例如 `unknown`、`en:null`、空字符串。是否把它们当缺失，取决于字段含义，必须逐列决定。

异常值、冲突、标签和不平衡也有明确规则，只是它们主要用数值范围、公式、允许集合和比例阈值表示，放在配置文件的 `outliers`、`conflicts`、`labels`、`imbalance` 部分，不容易一眼看出“这是一段定义”。

## 9. 清洗时必须记住

- 检测结果是证据，不是自动执行命令。
- 统计尾部、非标准条码可能是合理数据，不能一律删除。
- 清洗前必须先预览影响范围。
- 清洗后生成可追溯的新版本；如果确实覆盖原文件，必须在清单中记录父版本哈希。
- 每次修改都应记录改了什么、为什么改、影响了哪些行。

## 10. 检测结果如何交给处理工具

JSON 报告里的 `sample_row_ids` 只是给人看的样例，不能用于正式清洗。正式处理必须使用 finding 的 `selection_artifact_id`，读取对应的 Parquet 选择表。

### 10.1 单元格选择表

缺失、异常值、类型/格式、标签问题会为每个 finding 生成一张单元格表，字段是：

| 字段 | 含义 |
|---|---|
| `finding_id` | 对应的问题记录 |
| `rule_id` | 触发的规则 |
| `selection_type` | 固定为 `cell` |
| `row_index` | 当前数据版本中的 0 基行位置 |
| `row_id` | 数据自带行号；没有时回退为 `row_index:<位置>` |
| `column_index` | 列位置 |
| `column` | 列名 |
| `reason_code` | 具体原因，例如 `null`、`above_maximum`、`invalid_datetime` |
| `value_text` | 被标记单元格的原始内容文本 |
| `value_is_null` | 原始值是否为空 |

### 10.2 行选择表

字段冲突会生成行表，包含 `row_index`、`row_id`、`reason_code` 和 `row_values_json`。`row_values_json` 保存该规则比较到的字段值，方便追溯是哪一组值冲突。

### 10.3 重复分组表

每个重复规则生成一张完整分组表，而不是只给少量样例：

| 字段 | 含义 |
|---|---|
| `group_id` | 稳定分组编号 |
| `duplicate_key` | 参与比较的键值，JSON 文本 |
| `row_index` / `row_id` | 成员行定位 |
| `group_rank` | 组内顺序，1 为最先出现的行 |
| `group_size` | 该组总行数 |
| `is_candidate_keep` | 是否建议保留 |
| `is_redundant` | 是否建议视为冗余行 |

`is_candidate_keep` 只是“按当前顺序保留第一条”的候选，不代表业务上一定应该保留它。删除前仍需确认保留策略。

### 10.4 类别分布表

类别不平衡是数据集体级别的问题，没有逐行“修复”对象。检测工具会生成每列一张类别分布表，并在 finding 的 `distribution_artifact_id` 中记录位置。表中的 `count` 和 `share` 只统计有效标签。

### 10.5 约束类型与 `partial`

字段冲突检测现在明确支持：

- `formula`：字段换算公式；
- `relation`：字段大小或业务关系；
- `range`：数值范围；
- `unique`：组合键唯一；
- `allowed_values`：允许值集合；
- `conditional`：满足 `when` 条件时，另一个表达式必须成立；
- `custom`：需要外部适配器，当前不会假装执行。

如果某条约束缺少参数、表达式报错，或属于尚未实现的 `custom`，工具会返回 `partial` 并写入 `not_evaluated_constraints`，不会静默跳过还报告成功。

### 10.6 阈值和格式规则的位置

缺失、标签、不平衡、异常值、布尔值、日期格式、条码正则等参数都放在数据集 profile 中。检测代码只负责执行规则；换数据集时应修改 profile，而不是改检测器源码。

## 11. 检测前的数据接入

检测之前还有一层很薄的接入转换，由 profile 的 `ingestion` 段控制：

- `column_aliases`：把来源列名映射成统一字段名；
- `identifier_columns`：标识符强制按字符串读取，避免条码前导零丢失；
- `preserve_raw_columns`：保留来源列副本，便于追溯；
- `drop_unnamed_columns`、`strip_bom`、`case_sensitive_columns`：处理常见的表头问题；
- `ensure_row_id`：来源没有稳定行号时生成行号。

接入层不做缺失词转换、大小写统一、日期修复、数值插补或条码修复。这些属于检测后的清洗策略，必须由大模型选择并留下变更记录。
